# Гитарный тренажёр (Flutter + Flame)

Упрощённый аналог Yousician: слушает гитару через микрофон и в реальном времени
оценивает попадание в ноты. Полное ТЗ и план итераций — в
[guitar_trainer_prompt.md](guitar_trainer_prompt.md).

## Правила работы

- **Общение с пользователем — только на русском.** Комментарии в коде — на
  английском, текст интерфейса — на русском.
- Работаем итерациями (см. ТЗ). В начале итерации — план на 5–10 строк и вопросы,
  в конце — отчёт: что сделано, как проверить руками, что не получилось,
  ограничения, предложение текста коммита. После отчёта — стоп, ждать «ок».
- **Не делать `git commit` / `git push` и не трогать индекс (`git add`, `git rm`).**
  Коммиты пользователь делает сам; предлагать только текст коммита (на английском).
- Перед отчётом: `dart format .`, `flutter analyze` без замечаний, `flutter test`
  зелёный, сборка/запуск на Linux, по возможности проверка на Android-эмуляторе.
- Новые зависимости — только из списка ТЗ, остальные согласовывать
  (согласован `permission_handler`).
- Если что-то не работает на реальном устройстве — писать честно.

## Состояние

Итерации 0–7 приняты, итерация 8 (полировка) сделана и ждёт проверки. План MVP
из ТЗ на этом исчерпан; дальше — только по запросу пользователя (см. «После MVP»
в ТЗ).

Что есть: тюнер (YIN), 12 уроков в `assets/lessons/`, игровой экран на Flame
с метрономом, режимы «В темпе» и «Ожидание», оценка нот, счёт/серия, экран
результата со звёздами, прогресс и открытие уроков, настройки, калибровка
задержки, режим для левши, отработка фрагмента в цикле с автотемпом и поиском
трудного места, тёмная тема, иконка, анализ звука в изоляте.

Не проверено на реальной гитаре: пороги детектора атак и калибровка подобраны и
проверены только на синтезированном звуке (сквозные тесты).

## Архитектура

```
lib/
  audio/   MicCapture (flutter_recorder, f32 44.1 кГц моно), Yin, PitchTracker,
           OnsetDetector, NoteEventSource (PCM -> NoteEvent во времени песни),
           IsolateNoteEventSource (то же в фоновом изоляте; используется в UI),
           SoloudMetronome (flutter_soloud playScheduled), синтез щелчка
  music/   pitch (MIDI/частота/центы), GuitarTuning, Lesson/TabNote, парсер JSON
  engine/  чистый Dart, без Flutter/Flame/микрофона: SongClock, LessonPlayback,
           MetronomeScheduler, TempoScorer, WaitModeSession, ScoreKeeper,
           LessonResult, calibration, practice (трудное место, автотемп)
  game/    LessonGame (FlameGame 1280x720), компоненты, эффекты
  ui/      экраны и overlays
  data/    LessonRepository (AssetManifest), ProgressRepository, Settings
```

Ключевые решения:
- Время песни — от `Stopwatch` (`SongClock`), не накапливается из `dt`.
  Позиция ноты: `x = hitX + (noteTime − songTime) × px/с`.
- Метроном: щелчки ставятся через `SoLoud.playScheduled` относительно
  `getEngineTime()`; привязка заново при старте/продолжении/смене темпа.
  `MetronomeScheduler` считает доли по индексам (без дублей и пропусков).
- `NoteEventSource`: атаки — по скачку уровня в скользящем окне 1024 (шаг 256),
  с подтверждением через 60 мс (так отбрасываются щелчки нашего метронома);
  высота — YIN без сглаживания (окно 2048, шаг 1024). События отдаются по
  порядку с задержкой `delay` ≈ 70 мс.
- `TempoScorer`: окно ±120 мс (настраивается), точно — ±50 мс;
  `inputTime = eventTime − calibrationOffset`; `inputLag` откладывает закрытие
  окна на время анализа; окна в реальном времени (умножаются на скорость).
- Точность урока = очки / (100 × нот); звёзды 60/80/95%. Режим «Ожидание» без
  счёта и не сохраняется.
- Урок открывается после ≥1 звезды в предыдущем (порядок — по имени файла).
- Отработка фрагмента: `Lesson.excerpt(fromBar, toBar)` + `LessonGame(loop: true)`;
  проход заканчивается на тактовой черте, темп ±10% по итогам прохода
  (`nextSpeed`), результаты не сохраняются.
- Экран урока может замениться экраном урока (фрагмент): новый открывается до
  `dispose` старого. Поэтому старый сначала отпускает микрофон
  (`_releaseAudio`), `MicCapture.stop` гасит запись только если сам её начал,
  а ориентацию возвращает последний живой экран урока.
- Иконка рисуется кодом (`lib/ui/app_icon.dart`), PNG перегенерировать:
  `flutter test tool/generate_icons_test.dart` (Android адаптивная + Linux).

Тесты: `test/engine/end_to_end_test.dart` прогоняет все уроки через синтезатор
(`test/audio/synth.dart`) + `NoteEventSource` + движок. Новые уроки должны его
проходить.

## Окружение (ALT Linux)

- `/usr/bin/clang` в ALT — обёртка, которую не понимает сборщик нативных
  ассетов Flutter. Нужны скрипты-прокладки в `~/.local/bin/clang` и
  `clang++`, вызывающие `/usr/lib/llvm-19.1/bin/clang(++)`. На новом ПК с ALT —
  создать их заново.
- Нужен пакет `libalsa-devel` (для `flutter_recorder`).
- Если сборка Linux падает с «CMAKE_CXX_COMPILER is not a full path», удалить
  `build/linux` (кэш CMake со старым путём к компилятору).
- Android: AGP 9.4.1, Gradle 9.6.0, `compileSdk = 37` (требование
  `permission_handler_android` 14.1). Эмулятор: `Pixel_8`.
- Под Wayland нажимать кнопки в Linux-окне автоматически нельзя; для проверок
  экранов используется эмулятор (`adb shell input tap`, `uiautomator dump`).
